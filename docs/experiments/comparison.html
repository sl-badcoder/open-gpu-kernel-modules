01 · reclamation

Batched PMA free

Before: sixteen roots can cause sixteen PMA free calls.

Experiment: drain completion dependencies, then return root addresses in one PMA array call.

Preserves victim selection. Validate PMA callback synchronization and completion/state ordering.

batched-pma-free
02 · demand latency

Demand-first notifications

Before: one notified block can prefetch and wait for its whole chunk before the next notification.

Experiment: handle notified blocks first, then drain up to eight speculative triggers under the existing VA-space/GPU lifetime protection.

May help notification backlog; may delay useful lookahead for streaming access.

demand-first-notifications
03 · CPU selection work

Batched eviction selection

Before: repeatedly traverse used roots to find one victim.

Experiment: build a bounded candidate snapshot, then revalidate eligibility before claiming each root. Current free/unused/discarded roots retain priority.

Ranking is sampled within the window. Compare transfer volume and application runtime, not only scan cost.

batched-eviction-selection
04 · overlapping speculation

Coalesced prefetch

Before: concurrent triggers can revisit overlapping chunks.

Experiment: snapshot older in-flight windows, skip covered indices, and keep skipped attempts retryable.

Eight range-local slots. No completed residency cache. Serial workloads may see overhead with no benefit.

coalesced-prefetch

Tune after the branch comparison

Sequential/reused data: sweep prefetch 32 → 64 → 128 MiB. Sparse/random data: try 0 → 8 → 16 MiB. Zero disables speculative chunk prefetch, while full-block promotion can remain enabled.

Then sweep eviction batch 8 → 16 → 32 → 64. Keep 90/85 watermarks and 25 ms aging initially. Only afterward compare a narrower 90/88 gap or more headroom at 88/82. These are experimental starting points, not measured best settings.

Chunk size and promotion are writable at runtime. Watermarks, batch count and interval require a real module reload; calling modprobe on an already-loaded module does not update them.
